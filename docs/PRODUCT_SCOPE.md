# 제품범위와 운영 거버넌스

- 기준일: 2026-08-04
- 상태: 제안안
- 관련 총괄 이슈: #12

## 1. 제품 정의

방림명지로드힐 홈페이지는 다음 두 제품을 단계적으로 구성한다.

1. **공개 홈페이지**: 검증되고 공개 승인된 단지정보, 공지, 일정과 문서를 제공한다.
2. **입주민 포털**: 인증된 주민에게 개인화되거나 비공개인 서비스를 제공한다.

두 영역은 메뉴만 다르게 보이는 동일 화면이 아니라 URL, 인증, 권한, 저장데이터와 로그 수준이 분리된 시스템으로 설계한다.

## 2. 제품 원칙

1. 사실의 정확성이 시각적 홍보보다 우선한다.
2. 공개 가능한 정보와 주민·직원 전용 정보를 명확히 구분한다.
3. 기술관리자는 공식 콘텐츠의 승인권자가 아니다.
4. 게시물 변경과 권한 변경은 감사가능해야 한다.
5. 개인정보는 최소한으로 수집하고 목적이 끝나면 삭제한다.
6. 이미 검증된 외부서비스가 있는 기능은 자체개발보다 연동을 우선 검토한다.
7. 운영할 사람과 절차가 정해지지 않은 기능은 출시하지 않는다.

## 3. 사용자 유형

### 3.1 외부 방문자

- 공개 단지정보 열람
- 공개 공지와 일정 열람
- 관리사무소 연락처 확인
- 공개 문서 다운로드

개인정보를 제출하거나 주민전용 정보에 접근할 수 없다.

### 3.2 입주민

- 주민전용 공지·문서 열람
- 본인이 제출한 민원과 처리상태 확인
- 시설예약 또는 방문차량 서비스 이용
- 외부 전자투표 서비스로 이동

주민인증 방식과 계정복구 절차는 별도 보안설계 후 결정한다.

### 3.3 관리사무소 담당자

- 일반 공지와 관리일정 작성
- 민원·시설·차량 관련 운영
- 승인된 단지정보 유지관리

모든 게시물에 대한 무제한 승인권을 자동으로 부여하지 않는다.

### 3.4 입주자대표회의 관련 역할

- 소관 문서의 검토 또는 승인
- 공개 가능한 의결결과와 회의자료 관리

구체적 권한은 관리규약과 공식 의사결정에 따라 확정한다.

### 3.5 선거관리 관련 역할

- 선거·투표 관련 공지와 문서의 작성·검토·승인

일반 관리 게시권한과 분리한다. 현재 개인 이름을 코드나 권한모델에 고정하지 않는다.

### 3.6 감사 또는 읽기전용 검토자

- 게시·수정·승인·권한변경 이력 열람
- 필요한 감사자료 내보내기

일반 콘텐츠 수정권한은 부여하지 않는다.

### 3.7 기술관리자

- 배포, 장애대응, 백업, 복구, 계정기술지원

기술관리 권한만으로 공식 문서를 무기록 수정하거나 승인할 수 없어야 한다.

## 4. 정보분류

| 등급 | 설명 | 예시 | 기본 접근 |
|---|---|---|---|
| 공개 | 누구나 열람 가능 | 단지소개, 공개공지, 사무소 안내 | 인증 없음 |
| 주민전용 | 입주민만 열람 | 주민전용 공지, 일부 회의자료 | 주민인증 |
| 직원·위원회 전용 | 업무수행자만 접근 | 작성중 문서, 승인대기 자료 | 역할기반 접근 |
| 민감 | 개인 또는 제한된 담당자만 접근 | 민원내용, 차량정보, 계정복구 자료 | 최소권한·추가통제 |
| 감사·보안 | 지정된 관리자·감사만 접근 | 감사로그, 권한변경, 사고기록 | 강화된 접근통제 |

분류가 결정되지 않은 정보는 공개하지 않는다.

### 필수 기능

- 검증된 단지정보
- 공지 목록·상세·첨부파일

- 네이티브 앱

## 8. 콘텐츠 게시 워크플로

기본 상태:

```text
초안 -> 검토중 -> 승인 -> 예약 또는 게시 -> 보관
```

추가 상태:

- 반려
- 철회
- 정정
- 비공개 전환

모든 상태변경은 다음을 기록한다.

- 작업자
- 시각
- 변경 전 상태
- 변경 후 상태
- 변경 내용
- 변경 이유
- 승인자

게시된 내용은 기존 기록을 덮어써서 사라지게 하지 않는다.

## 9. 권한 원칙

### 최소권한

업무에 필요한 기능만 부여한다.

### 역할분리

작성, 검토, 승인, 게시, 기술운영을 가능한 범위에서 분리한다.

### 소관분리

선거 관련 공지는 일반 관리 공지와 별도 권한으로 관리한다.

### 이력보존

권한을 부여·변경·회수한 사실도 감사로그에 남긴다.

### 퇴임·퇴사 처리

계정 접근은 즉시 중단하되 과거 기록의 작성자 표시는 보존한다.

## 10. 데이터 원칙

기능별로 다음 질문에 답하지 못하면 구현하지 않는다.

1. 어떤 데이터를 수집하는가?
2. 왜 필요한가?
3. 누가 열람하는가?
4. 어디에 저장하는가?
5. 외부로 전송하는가?
6. 얼마 동안 보관하는가?
7. 삭제 또는 정정 요청은 어떻게 처리하는가?
8. 사고 발생 시 누가 대응하는가?

## 12. 승인 필요 결정

개발 전에 다음을 공식적으로 결정해야 한다.

- 사이트가 공식 홈페이지인지 비공식 프로젝트인지
- 운영주체와 최종 게시 승인자
- 공식 한국어·영어 명칭
- 공개 가능한 문서 범위
- 실제 관리사무소 연락처와 운영시간
- 사진촬영·게시 권한
- 입주민 인증 방식
- 개인정보 처리주체
- 외부서비스 계약주체
- 장애와 민원 대응 담당자

## 13. 범위 변경 규칙

새 기능을 추가하려면 이슈에 다음을 작성한다.

- 사용자 문제
- 대상 사용자
- 공개등급
- 수집데이터
- 운영담당자
- 보관기간
- 보안·접근성 영향
- 완료조건
- 배포와 롤백 방법

화면에 버튼을 먼저 추가하고 나중에 운영방식을 정하는 순서를 금지한다.
