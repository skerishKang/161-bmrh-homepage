# 공식 콘텐츠 검증 기준

- 기준일: 2026-08-04
- 관련 이슈: #2, #3
- 목적: 홈페이지에 게시되는 단지정보, 연락처, 사진, 문구와 문서가 사실에 부합하고 공개권한을 갖도록 한다.

## 1. 기본원칙

1. 출처를 확인할 수 없는 정보는 공식 사실로 게시하지 않는다.
2. 임시값은 실제값처럼 보이지 않게 명확히 표시한다.
3. 동일 정보는 한곳에서 관리하고 한국어·영어 화면이 같은 원본을 사용한다.
4. 검증일과 검증자를 기록한다.
5. 주민 개인정보, 내부자료와 분쟁자료는 공개 저장소에 올리지 않는다.
6. 사진은 실제 단지 사진인지와 게시권한을 모두 확인한다.
7. 홍보 문구는 객관적 근거가 있는 범위로 제한한다.

## 3. 허용 가능한 출처

우선순위가 높은 출처:

1. 공식 건축·행정 기록
2. K-APT 등 공식 공동주택 정보
3. 관리사무소가 보유한 승인된 자료
4. 입주자대표회의 또는 권한 있는 주체가 승인한 문서
5. 시공사·공급사의 공식 자료

보조 출처:

- 지도서비스
- 언론기사
- 부동산 플랫폼
- 개인 블로그
- 커뮤니티 게시물

보조 출처는 단독으로 공식정보 확정에 사용하지 않는다.

## 4. 정보 불일치 처리

출처끼리 값이 다르면 다음 순서로 처리한다.

1. 게시를 보류하거나 `확인 중`으로 표시한다.
2. 출처의 기준일과 정의를 확인한다.
3. 관리사무소 또는 공식 기록으로 재확인한다.
4. 최종값과 선택이유를 검증표에 기록한다.
5. 이미 게시된 값이 틀렸다면 정정일과 이전값을 보존한다.

단순히 가장 최근에 보이는 웹페이지 값을 선택하지 않는다.

## 5. 사진 검증

각 이미지에 다음 정보를 기록한다.

| 필드 | 내용 |
|---|---|
| 파일명 | 저장소 또는 스토리지의 파일명 |
| 촬영대상 | 단지전경, 출입구, 조경 등 |
| 촬영일 | 알 수 있으면 기록 |
| 촬영자·권리자 | 저작권 또는 사용권 보유자 |
| 게시허가 | 승인자와 승인일 |
| 개인정보 점검 | 얼굴, 차량번호, 세대호수, 우편물 등 |
| 편집내용 | 흐림처리, 크롭, 색상보정 등 |
| 대체텍스트 | 화면을 보지 못하는 사용자를 위한 설명 |
| 공개등급 | 공개, 주민전용, 사용금지 |

### 사용금지

- 다른 아파트를 실제 단지처럼 표시하는 사진
- 출처와 사용권을 확인할 수 없는 사진
- 주민 얼굴이나 차량번호가 식별되는데 동의·비식별 처리가 없는 사진
- 보안설비 위치를 과도하게 드러내는 사진
- 내부 전용 문서나 개인정보가 배경에 노출된 사진

## 6. 문구 검증

다음 표현은 근거를 확인한 경우에만 사용한다.

- 프리미엄
- 우수한 학군
- 사통팔달
- 최첨단
- 스마트 주거
- 친환경
- 안전한 단지
- 최고의 입지
- 주민만족도

권장 방향:

- 과장형: `최고의 교육환경`
- 사실형: `방림초등학교까지 지도상 약 ○m이며 실제 통학경로는 확인이 필요합니다.`

- 과장형: `최첨단 스마트 주거`
- 사실형: `공동현관 출입시스템과 무인택배함 운영 여부를 확인해 안내합니다.`

객관적 근거가 없다면 삭제한다.

## 7. 영문표기

- 공식 영문명이 없다면 임의의 브랜드를 공식명칭처럼 사용하지 않는다.
- 주소는 일관된 로마자 표기를 사용한다.
- 한국어와 영어에서 세대수, 날짜, 연락처가 달라지지 않게 같은 데이터 원본을 사용한다.
- 번역이 확정되지 않은 항목은 영어 페이지에서 숨기거나 검토중임을 표시한다.

## 8. 연락처

공개 전에 확인할 사항:

- 실제 관리사무소 대표번호인가
- 개인 휴대전화가 아닌가
- 홈페이지 공개 승인을 받았는가
- 운영시간과 휴무일이 정확한가
- 비상상황과 일반문의 번호가 구분되는가
- 번호 변경 시 누가 수정하는가

임시번호를 실제번호 형식으로 넣지 않는다. 필요하면 `연락처 확인 중`이라고 표시한다.

## 9. 문서와 첨부파일

공개 전에 다음을 점검한다.

- 공개권한
- 개인정보와 서명·도장·연락처 노출
- 파일명
- 작성일·시행일·게시일
- 최종본 여부
- 스캔 품질
- 검색 가능한 텍스트 또는 접근 가능한 대체수단
- 악성파일 검사
- 이전 버전과 정정 여부

원본 내부문서를 공개 저장소에 직접 커밋하기보다 승인된 게시본을 별도 스토리지에서 관리하는 방식을 권장한다.

## 10. 공지 게시 체크리스트

- [ ] 제목이 내용을 정확히 설명한다.
- [ ] 게시주체와 문의처가 확인되었다.
- [ ] 날짜·시간·장소가 정확하다.
- [ ] 대상 주민이 명확하다.
- [ ] 필요한 행동과 기한이 명확하다.
- [ ] 첨부파일이 최종본이다.
- [ ] 개인정보가 제거되었다.
- [ ] 공개/주민전용 분류가 맞다.
- [ ] 검토자와 승인자가 기록되었다.
- [ ] 정정·철회 방법이 정해졌다.
- [ ] 모바일에서 읽을 수 있다.
- [ ] 링크공유 미리보기가 적절하다.

## 11. 정기 재검증

| 항목 | 권장 주기 |
|---|---|
| 전화번호·운영시간 | 분기 또는 변경 즉시 |
| 관리주체·운영주체 | 변경 즉시 |
| 기본 단지정보 | 연 1회 |
| 외부 링크 | 월 1회 자동검사 |
| 사진 게시권한 | 연 1회 또는 권리변경 시 |
| 개인정보처리방침 | 기능변경 전후 및 연 1회 |
| 공지·문서 공개상태 | 보관정책에 따라 정기검토 |

## 12. 승인기록 최소형식

```text
항목:
변경 전:
변경 후:
근거 출처:
검증일:
검증자 역할:
공개 승인자 역할:
승인일:
비고:
```

공개 GitHub 이슈나 PR에는 개인 전화번호, 서명, 신분증, 내부 문서 원본을 첨부하지 않는다. 필요한 승인증거는 접근제한된 보관소의 식별자만 기록한다.
