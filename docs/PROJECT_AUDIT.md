## 1. 요약

현재 프로젝트는 방림명지로드힐을 위한 정적 홍보·포털 UI 시안입니다. 화면에는 단지소개, 공지, 커뮤니티, 생활편의, 전자투표, 시설예약, 방문차량, 민원접수와 로그인 요소가 배치되어 있지만 대부분 실제 기능과 연결되지 않았습니다.

디자인 베이스는 재사용할 수 있으나 다음 이유로 공식 운영 사이트로 사용할 수 없습니다.

- CSS Grid 속성 오타로 핵심 레이아웃이 브라우저에서 무시될 수 있음
- 단지 기본정보와 연락처가 공식 검증되지 않음
- 실제 단지 사진 대신 일반 외부 이미지 사용
- 비공식 브랜드와 근거가 확인되지 않은 홍보 문구 사용
- 여러 메뉴가 동일한 준비중 화면으로 연결됨
- 로그인, 관리자, 데이터베이스, 역할권한, 감사로그 부재
- 개인정보, 보안, 접근성, 자동검사와 출시 승인 절차 부재

따라서 현재 코드는 완성된 홈페이지가 아니라 제품 방향과 UI를 검토하기 위한 프로토타입으로 표시해야 합니다.

## 2. 현재 구조

```text
index.html
css/style.css
js/script.js
netlify.toml
```

- `index.html`: 홈, 단지정보, 갤러리, 서비스 진입카드, 푸터
- `css/style.css`: 컬러변수, 애니메이션, 반응형 스타일
- `js/script.js`: 한국어·영어 전환, 홈·준비중 탭, 모바일 메뉴
- `netlify.toml`: 저장소 루트를 게시하는 정적 배포 설정

초기 React/Vite 구조에서 Vanilla HTML/CSS/JavaScript로 전환한 흔적이 남아 있습니다. 실제 배포구조와 사용하지 않는 패키지·파일은 향후 기술구조 확정 시 정리해야 합니다.

## 3. 재사용 가능한 장점

### 시각적 방향성

- 네이비와 골드 중심의 일관된 컬러체계
- 히어로, 정보카드, 서비스카드, 갤러리, 푸터의 명확한 화면구조
- 데스크톱·모바일 내비게이션 고려
- 한국어·영어 텍스트 사전 분리

### 확장 가능한 메뉴개념

- 공지
- 단지소개
- 생활편의
- 전자투표
- 시설예약
- 방문차량
- 민원접수

이 메뉴들은 현재 기능이 아니라 향후 범위 후보입니다.

### 단순한 공개 MVP 가능성

첫 단계에서 읽기 중심 공개 홈페이지로 제한하면 복잡한 주민 개인정보 시스템 없이도 정상화할 수 있습니다.

## 5. 콘텐츠 신뢰성

아파트 공식 사이트에서는 디자인보다 사실의 정확성이 우선입니다. 주소, 세대수, 동 수, 사용승인일, 난방방식, 시공사, 연락처와 운영시간을 하나의 검증된 데이터 원본에서 관리해야 합니다.

현재처럼 정보가 HTML과 번역 JavaScript에 중복되면 한국어와 영어가 서로 다른 값을 표시할 수 있습니다.

권장사항:

- 공식정보를 JSON, CMS 또는 데이터베이스 한곳에서 관리
- 항목별 출처와 검증일 기록
- 권한 있는 검토자의 승인기록
- 임시값은 `미확정` 또는 `확인 중`으로 명시

## 6. 디자인과 실제 단지의 일치

현재 UI는 고급 분양 홍보 사이트의 표현을 사용합니다. 공식 관리 홈페이지로 발전시킬 때는 프리미엄 이미지보다 정확한 공지, 기록보존과 주민편의를 우선해야 합니다.

실제로 존재하지 않는 시설·브랜드·스마트 시스템을 암시해서는 안 됩니다. 사진은 실제 촬영물인지, 게시권한이 있는지, 얼굴·차량번호·세대정보가 노출되지 않는지 확인해야 합니다.

## 8. 게시와 기록 거버넌스

기본 게시상태:

```text
초안 -> 검토중 -> 승인 -> 예약/게시 -> 보관
```

반려, 철회, 정정과 비공개 전환 상태도 필요합니다. 게시 후 변경 시 이전버전, 변경자, 변경시각, 변경이유와 승인자를 보존해야 합니다. 흔적 없는 교체·삭제를 허용하지 않습니다.

## 9. 접근성

필수 개선:

- 이동은 `<a>`, 실행은 `<button>` 사용
- 현재 페이지 `aria-current`
- 모바일 메뉴 `aria-expanded`, `aria-controls`
- 메뉴·대화상자 포커스 이동과 복귀
- Escape 키 닫기
- 명확한 `:focus-visible`
- `prefers-reduced-motion`
- 200% 확대와 한국어·영어 길이 검증

## 10. 보안과 개인정보

로그인, 민원, 차량, 예약 또는 파일업로드가 추가되는 순간 개인정보 시스템이 됩니다. 기능개발 전에 다음을 정해야 합니다.

- 어떤 데이터를 왜 수집하는가
- 누가 열람하는가
- 어디에 저장하는가
- 언제 삭제하는가
- 외부업체로 전달하는가
- 사고 발생 시 누가 대응하는가

전자투표는 본인확인, 비밀성, 무결성, 중복방지, 감사와 이의제기 절차가 필요하므로 자체개발보다 검증된 외부서비스 연결을 우선 검토합니다.

## 13. 결론
